B. Download and preprocess a sample

This page downloads one LSA SAF product sample, crops it to a configured study area, and remaps it to a target grid. Begin with one product and one short time period. Validate the result before extending the period or region.

1. Check the product and study area

The example defaults to METREF. The repository also lists FVC/MDFVC as an example product. Select a product from the LSA SAF Data Service and confirm its product URL, time coverage, variable names, units, coordinate system, no-data values and quality flags.

Coordinates are longitude/latitude in degrees in this example. For a new AOI, store it in data/aoi/ and there is a utils/ script to convert a shapefile to a bounding box. The AOI is used to crop the raw files before remapping and using standrdized coordinates. The target grid is defined in code/preprocess_utils/grid.txt. The default is a 0.05° global grid, but you can change the resolution and bounds to suit your study area.

The remapping method is bilinear by default. Use nearest-neighbour for categorical fields and flags. The remapping method is set in code/preprocess_utils/config_resolution.yaml.

2. Set credentials

From the repository root:

cp code/.env.example code/.env

Edit code/.env and enter your LSA SAF credentials - See the setup guide for details. The downloader expects:

LSASAF_USERNAME=your_username
LSASAF_PASSWORD=your_password
SAMPLE_YEAR=2020
SAMPLE_MONTH=06
VARIABLE_NAME=METREF
URL=https://datalsasaf.lsasvcs.ipma.pt/PRODUCTS/MSG/METREF/NETCDF

Keep code/.env private and never commit it. The script reads this path by default when run from the repository root. If you use another path, set ENV_FILE=/path/to/.env.

3. Download the sample

Run from the repository root:

bash code/01_download_sample.sh

You can override the year, month, product and product URL positionally:

bash code/01_download_sample.sh 2020 06 METREF "https://datalsasaf.lsasvcs.ipma.pt/PRODUCTS/MSG/METREF/NETCDF"

The script checks the service listing and skips files already present. New files are first written as .part, then renamed after a successful download. The default raw-data layout is:

data/raw/METREF/2020/06/*.nc

Confirm that files exist and have plausible sizes. A completed download only confirms transfer success; it does not confirm that the data are scientifically valid.

4. Inspect raw NetCDF before processing

Use CDO to list metadata and summary information:

cdo -s sinfo data/raw/METREF/2020/06/example.nc
cdo -s showname data/raw/METREF/2020/06/example.nc
cdo -s showtimestamp data/raw/METREF/2020/06/example.nc
cdo -s infon data/raw/METREF/2020/06/example.nc

Replace example.nc with a real downloaded filename. Review coordinate ranges, variable names, timestamps, units, missing values and product QA information. If the raw file itself has no valid values, diagnose the download/product selection before remapping.

5. Choose variables and crop/remap

Inspect the exact variable names:

cdo -s showname data/raw/METREF/2020/06/example.nc

Set the main continuous variable, AOI file and optional QA variable names:

MAIN_VARIABLE=METREF \
QA_VARIABLES=QUALITY_FLAG,QC_FLAG \
AOI_GEOJSON=data/aoi/study_area.geojson \
bash code/02_preprocess_cdo.sh data/raw/METREF data/interim

Use exact variable names from showname; QA names are comma-separated. Omit QA_VARIABLES if no QA layers are needed. The pipeline builds one snapped AOI grid from the first raw file, then checks other inputs use the same grid. It selects and bilinearly remaps only MAIN_VARIABLE by default. QA layers are selected and processed separately with nearest-neighbour mapping, which chooses an existing code rather than averaging categories. Set MAIN_REMAP_METHOD=nearest if the primary variable is categorical.

The crop includes a one-cell margin by default to support remapping near AOI edges. Outputs are written to temporary files, checked for readability and valid main-variable cells, and renamed only when complete. QA values are preserved as data layers; this example does not interpret product-specific bit fields or automatically apply a QA mask.

PARALLEL controls independent files processed concurrently; for example:

PARALLEL=2 MAIN_VARIABLE=METREF AOI_GEOJSON=data/aoi/study_area.geojson \
  bash code/02_preprocess_cdo.sh data/raw/METREF data/interim

Start conservatively. Increase parallelism only after checking RAM, disk throughput and temporary storage.

Processed files are written beneath data/interim/<MAIN_VARIABLE>/YYYY/MM/. Check data/interim/cdo.log, then inspect an output:

cdo -s sinfo data/interim/METREF/2020/06/example_processed.nc
cdo -s infon data/interim/METREF/2020/06/example_processed.nc

6. Check for missing values

Compare raw and processed summaries and map the output. An all-NaN or mostly missing result can be caused by:

  • crop bounds and target-grid bounds not overlapping;
  • AOI partly outside raw source coverage (output is limited to its overlap);
  • wrong variable, coordinate names or coordinate direction;
  • fill values not decoded as missing;
  • a source mask or retrieval-quality exclusion;
  • invalid or unsupported remapping setup.

Some missing values are expected. Set an acceptable valid-coverage threshold for the application, and check coverage spatially as well as numerically. A file existing or opening is not enough to establish fitness for use.

7. Method caveats

  • Regridding does not add source detail. A finer target grid interpolates the source; it does not make the measurement higher resolution.
  • Bilinear interpolation smooths continuous fields; nearest-neighbour preserves category labels but may look blocky.
  • Degree-based cell size changes with latitude.
  • Preserve product QA flags and document any masks, unit conversion and temporal aggregation.
  • Record the input product/version, AOI bounds, output grid, resolution, remapping method and software version.
