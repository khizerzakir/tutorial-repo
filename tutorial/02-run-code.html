B · Download and preprocess

Run the download and preprocessing scripts to get a small sample of LSA SAF data, crop it to your area of interest, and remap it to a regular grid.

A · Setup B · Download & preprocess C · Zarr cube D · Explore

You will run two scripts from the repository root, in the Linux/WSL terminal you opened in Setup:

Script Input Output
code/01_download_sample.sh LSA SAF server + code/.env data/raw/<PRODUCT>/YYYY/MM/*.nc
code/02_preprocess_cdo.sh raw NetCDF + AOI/YAML bounds data/interim/<PRODUCT>/YYYY/MM/*_processed.nc 
cd ~/projects/tutorial-repo     # every command on this page runs from here

Prefer to fill in a form? The command builder writes all the commands on this page for your product, month, AOI and number of CPU cores.

1 · Download one month

Run it

  • Use code/.env
  • Choose the month
  • Another product (FVC)
  • Faster / elsewhere

Uses SAMPLE_YEAR, SAMPLE_MONTH, VARIABLE_NAME and URL from code/.env:

bash code/01_download_sample.sh

Positional arguments override code/.env: YYYY MM [PRODUCT] [URL].

bash code/01_download_sample.sh 2015 06 METREF

The product name is used for the output folder; the URL decides what is downloaded.

bash code/01_download_sample.sh 2015 06 MDFVC \
  "https://datalsasaf.lsasvcs.ipma.pt/PRODUCTS/MSG/MDFVC/NETCDF"
JOBS=8 RAW_DIR=/data/lsasaf bash code/01_download_sample.sh 2015 06 METREF

Options

Setting How to set it Default Meaning
YYYY MM 1st, 2nd argument SAMPLE_YEAR, SAMPLE_MONTH in .env Month to download
PRODUCT 3rd argument .env VARIABLE_NAME → METREF Folder name under data/raw/
URL 4th argument .env URL Product NetCDF root on the LSA SAF server
JOBS environment variable 4 Parallel downloads
RAW_DIR environment variable data/raw Where raw files go
ENV_FILE environment variable ./code/.env Credentials/settings file

code/.env is loaded after environment variables, so URL=… bash code/01_download_sample.sh is overwritten by the URL line in .env. Override the month, product and URL with arguments.

Example output

2015-06: 30 file(s) on server, 30 to download -> …/data/raw/METREF/2015/06
First file: ~6s. Estimated remaining: ~0m44s with 4 parallel jobs
Done: 30 file(s) in 0m52s

Re-running is safe: files that already exist are skipped and only failed ones are retried.

NoteWalk through the download script 
code/01_download_sample.sh (simplified)
ENV_FILE="${ENV_FILE:-$PWD/code/.env}"
1set -a; . "$ENV_FILE"; set +a
WGETRC="$(mktemp)"; trap 'rm -f "$WGETRC"' EXIT
2printf 'http_user=%s\nhttp_password=%s\n' "$LSASAF_USERNAME" "$LSASAF_PASSWORD" > "$WGETRC"

3for d in $(seq -w 1 31); do
  list+=$(wget -q -O- "$SRC/$YEAR/$MONTH/$d/" | grep -E '\.nc$' …)
done

4get() { wget -q -O "$f.part" "$1" && mv "$f.part" "$f"; }
5xargs -P "$JOBS" -I{} bash -c 'get "$1" "$2"' _ {} "$DEST"
1
Credentials and defaults come from the private .env, never from the repository.
2
wget reads the password from a temporary file that is deleted on exit — it never appears in the process list.
3
Each day folder of the month is listed; days that do not exist return nothing.
4
Files are written as .part and renamed only when complete — an interrupted run never leaves a “finished-looking” half file.
5
JOBS downloads run in parallel.

2 · Inspect a raw file

Never remap blind. Pick one file and look at variable names, grid and values:

f=$(ls data/raw/METREF/2015/06/*.nc | head -n1); echo "$f"
cdo -s showname      "$f"   # variable names → MAIN_VARIABLE and QA_VARIABLES
cdo -s sinfo         "$f"   # grid: lon/lat range and step, data type
cdo -s showtimestamp "$f"   # time stamp
cdo -s infon         "$f"   # min / mean / max per variable and number of missing values
TipCheck yourself
  • showname lists the product variable (e.g. METREF) and a QA variable (e.g. quality_flag).
  • sinfo shows a regular lonlat grid (for MSG-disk products e.g. -80 to 80 by 0.05).
  • infon shows plausible values for the product (METREF: mm/day, roughly 0–15).

3 · Define the region

The region can come from the YAML bounds or from a vector file. Either way the script snaps it outward to whole raw-grid cells and writes the target grid to code/preprocess_utils/grid.txt.

  • Bounding box in YAML
  • Vector AOI file

Edit code/preprocess_utils/config_resolution.yaml:

code/preprocess_utils/config_resolution.yaml
1domain:
  lon_min: -17.275
  lon_max: -11.225
  lat_min: 12.225
  lat_max: 16.775
processing:
2  parallel: 4
3  remap_method: bilinear
4  buffer: 0.2
1
Degrees (EPSG:4326). Snapped outward to raw cell edges on each run.
2
Files processed at the same time. This is the only place to set parallelism for preprocessing — an environment variable PARALLEL= is ignored.
3
bilinear for continuous fields, nearest for categorical ones. Applies to all non-QA variables; QA variables always use nearest neighbour.
4
Extra degrees cropped around the grid, so bilinear interpolation has real neighbours at the AOI edge.

Pass any GeoPandas-readable file (.shp, .gpkg, .geojson, .parquet) as the 4th argument (or AOI_FILE=). Its total bounds become the domain:

MAIN_VARIABLE=METREF uv run bash code/02_preprocess_cdo.sh \
  0.05 data/raw/METREF data/interim/METREF data/aoi/spatial_units.geosjon
ImportantThe script updates the YAML in place

Each run rewrites the domain: and grid: sections of config_resolution.yaml with the snapped bounds (and with the AOI bounds when you pass a vector file). Commit or copy the file if you want to keep the previous region; restore the repository default with git checkout code/preprocess_utils/config_resolution.yaml code/preprocess_utils/grid.txt.

4 · Crop and remap

Run it

1export MAIN_VARIABLE=METREF
2export QA_VARIABLES=quality_flag
3uv run bash code/02_preprocess_cdo.sh 0.05 data/raw/METREF data/interim/METREF
1
Required. Must match a name from cdo showname; the script stops and lists the available names otherwise.
2
Comma-separated QA/flag variables, remapped with nearest neighbour so flag codes are never averaged. Default quality_flag; every name must exist in the file.
3
uv run makes python3 inside the script use the project environment (YAML + grid helper). Arguments: resolution label (written to the log — the target grid always follows the raw grid’s cell size, 0.05° for MSG, so no false detail is created), input folder (searched recursively for *.nc) and output folder (use one folder per product so the cube builder never mixes products).

All options

Setting How to set it Default
resolution label 1st argument YAML processing.resolution
input folder 2nd argument data/raw
output folder 3rd argument data/interim
AOI vector file 4th argument or AOI_FILE= none → YAML domain
MAIN_VARIABLE environment variable — (required)
QA_VARIABLES environment variable quality_flag
CONFIG_FILE environment variable code/preprocess_utils/config_resolution.yaml
parallel files, remap method, buffer YAML processing: 4, bilinear, 0.2

NoteWalk through one file’s journey (process_cdo) 
code/02_preprocess_cdo.sh (per file)
1cdo -sellonlatbox,$CLIP_WEST,$CLIP_EAST,$CLIP_SOUTH,$CLIP_NORTH  in.nc  clip.nc
2cdo -delname,$QA_CSV  clip.nc  main.nc
cdo -selname,$QA_CSV  clip.nc  qa.nc
3cdo -remapbil,grid.txt  main.nc  main_remap.nc
4cdo -remapnn,grid.txt   qa.nc    qa_remap.nc
5cdo merge main_remap.nc qa_remap.nc merged.nc
6cdo -s sinfo merged.nc && mv merged.nc out.nc.part && mv out.nc.part out_processed.nc
1
Crop to the target grid plus the buffer, so interpolation at the edge has neighbours.
2
Split continuous variables from QA flags.
3
Continuous variables: bilinear (or nearest, from the YAML).
4
Flags: always nearest neighbour — a flag value is a code, not a number to average.
5
Put them back together.
6
Only a readable result is renamed into place; temp files are removed on any failure. Existing valid outputs are skipped, so re-running resumes.

5 · Check the output

ls data/interim/METREF/2015/06 | head -n3
tail -n 3 data/interim/METREF/cdo.log           # status=processed / failed per file
grep -c "status=processed" data/interim/METREF/cdo.log
f=$(ls data/interim/METREF/2015/06/*_processed.nc | head -n1)
cdo -s sinfo "$f"                                # 121x91 lonlat grid, METREF + quality_flag
cdo -s infon "$f"                                # compare min/mean/max with the raw file
TipCheck yourself
  • One *_processed.nc per raw file, and no status=failed lines in cdo.log.
  • The grid matches code/preprocess_utils/grid.txt.
  • Value ranges are close to the raw file’s; the number of missing values is plausible (ocean, masks).

When output is mostly missing

Likely cause Check
AOI outside product coverage Compare sinfo ranges of raw file and grid.txt
Wrong variable cdo showname vs MAIN_VARIABLE
Fill values not decoded cdo infon on the raw file: are huge negative values counted as data?
Real masks (sea, clouds, retrieval QA) Inspect quality_flag and the product user manual
ModuleNotFoundError: yaml / xarray Run the script via uv run bash … or source .venv/bin/activate
QA variable 'quality_flag' not found Set QA_VARIABLES to the flag name your product uses (see showname)

Method notes

  • Regridding never adds detail: a finer target grid only interpolates the source.
  • Bilinear smooths continuous fields (extremes can shrink); nearest keeps categories but looks blocky.
  • Degree cells shrink with latitude (0.05° ≈ 5.5 km at the equator, ≈ 5.3 km at 15° N in longitude).
  • Record product version, AOI, grid, remap method and software versions with your results.
